# 🍠 小红书文案批量生成器

一个纯前端（HTML + CSS + JavaScript）的单页面小工具：选择行业，输入主题、目标人群、关键词和语气风格，一次批量生成 1–20 篇小红书笔记文案，并配好**封面图**和**配图建议**；还能**自动检测违禁词**、带入**你自己的身份档案和真实案例**、把现场随手记**整理成笔记**、规划**内容日历**、**拆解爆款**、生成**评论私信回复**、**一稿多用**和**效果统计**。

- 不需要安装任何东西，**双击 `index.html` 就能用**
- 可以一键部署到 **GitHub Pages**
- 没有后端，所有数据（包括 API Key、档案、案例、历史记录）**只保存在你自己的浏览器里**，可以一键备份到文件，在手机和电脑之间转移

### 界面分区

| 分区 | 里面有什么 |
| --- | --- |
| ✍️ 生成 | 批量生成文案（原有功能），每篇自带违禁词检测、封面、配图建议、一稿多用 |
| 🛠 工具 | 🛡 违禁词检测 · 📝 素材变笔记 · 🔍 爆款拆解 · 💬 回复话术 |
| 📚 资料库 | 身份 / 账号档案、真实案例库 |
| 🗓 日历 | 7 / 14 / 30 天内容规划 |
| 📊 数据 | 效果回填、统计、全部数据备份与导入 |

电脑上分区在顶部，手机上在屏幕底部，单手就能切换。

## 🚀 怎么打开使用

### 方式一：本地直接打开（最简单）

1. 下载本仓库：点击 GitHub 页面上的绿色 **Code** 按钮 → **Download ZIP**，解压。
2. 双击 `index.html`，用 Chrome / Edge / Safari 等浏览器打开即可。

### 方式二：在线使用

部署到 GitHub Pages 后（见下文），直接访问 `https://你的用户名.github.io/xhs-copy-generator/`，手机上也可以打开，还能「添加到主屏幕」。

### 使用步骤

1. 选择 **行业**（以及细分方向，选「不限」则每篇随机一个方向），填写 **主题/产品**（必填），以及目标人群、关键词（输入后按回车或逗号添加，可以加多个）。
2. 选择 **语气风格** 和 **生成数量**。
3. 选择 **生成模式**：
   - **模板模式**：直接点「开始生成」，马上出结果。
   - **AI 模式**：第一次使用需要先在右上角「⚙️ 设置」里填写 API Key（见下一节）。
4. 生成后，点每篇右上角的「📋 一键复制」，粘贴到小红书即可；或者点顶部的「CSV / TXT」把全部文案导出。
5. 每篇卡片上会显示 **合规检测** 结果、**封面** 和 **配图建议**，右上角还有「♻️ 一稿多用」（见下文）。
6. 右上角「🕘 历史」可以找回之前生成的内容。

> 💡 想让文案更真实：先去「📚 资料库」建好你的身份档案和几个真实案例，生成时在「带入我的资料」里选上。

## 🛡 违禁词 / 限流词检测

**自动检测**：每篇文案生成后，标题、正文、互动引导、话题标签和封面大字都会自动检测：

- 卡片标题旁显示「✅ 合规」或「⚠️ N 处违禁/限流词」；
- 命中的词在文中**标红（高风险）或标橙（容易限流）**，鼠标悬停可看原因和建议；
- 「🛡 合规检测」面板按分类列出：**广告法极限词**（最、第一、顶级、100%、绝对…）、**夸大功效 / 承诺**（根治、零风险、包过、永不变形…）、**导流词**（加微信、私信报价、电话号码、二维码、网址…）、**价格诱导**（全网最低、跳楼价、清仓、仅限今天…）；
- 点建议词即可替换（同一个词全部替换），或点「一键全部替换」。替换结果会同步保存到历史记录。

**单独检测**：「🛠 工具 → 🛡 违禁词检测」，粘贴任意文案（别人写的笔记、评论回复、海报文字…）即可检测和替换。

**修改词库**：

- 完整词库在 **`banned-words.js`**，用记事本或任何代码编辑器打开就能改。每条格式是 `['词', '分类', ['替换建议1', '替换建议2'], '等级']`，等级 `high` 标红、`medium` 标橙；正则规则（手机号、邮箱、网址等）在 `patterns` 里；`phraseWhitelist` 是不算违规的短语（比如“第一次”“安全第一”“做到天花板”）。
- 不想改文件的话，在「违禁词检测」页面底部的「自定义词库」里加词，格式 `词=替换1/替换2`，只保存在本机浏览器。
- AI 模式下，提示词里也会要求 Claude 避开这些词。

> 词库根据《广告法》常见极限用语和小红书社区规范整理，仅供参考，平台规则会变化，请以官方最新规定为准。

## 📚 我的资料库

在「📚 资料库」里维护两类资料（都只保存在本机浏览器）：

**身份 / 账号档案**（可以建多个，比如门窗号、潜水号各一个）：档案名称、身份、服务区域、从业年限、特色 / 优势、说话风格、常用结尾。

**真实案例库**：行业 / 细分、时间、城市、客户情况、问题、解决方案、费用、结果、备注。

**生成时带入**：在「✍️ 生成」页的「带入我的资料」里选择档案和案例（可多选案例，批量生成时每篇轮流带入一个）：

- **模板模式**：正文会加入第一人称的自我介绍（身份、区域、年限、特色），一段写有时间、城市、问题、做法、费用、结果的“真实案例”段落，标题里会有一个案例标题，话题标签加上案例城市，结尾加上你的常用结尾；细分方向选“不限”时，会按案例的细分方向来写。
- **AI 模式**：档案和案例会作为【账号档案】【真实案例】发给 Claude，要求用你的身份和说话风格来写，保留案例里的具体细节，不编造资料里没有的数字和效果。

也可以在案例卡片上点「用这个案例写笔记」，自动切换到生成页并选好行业和案例。

> 🔒 请不要在案例里写客户真实姓名、门牌号、电话等隐私信息。

## 📝 素材变笔记

「🛠 工具 → 📝 素材变笔记」：选择行业和细分，把现场随手记的要点（每行一条）和照片描述（每行一张）贴进来，点「✨ 整理成笔记」。

- 会自动识别时间、城市、客户情况、问题、做法、费用和结果，整理成“现场情况 → 具体做法 → 结果 → 图片说明”的真实体验笔记；装修类写成“项目记录”，潜水写成“潜水日记”，美食写成“探店记录”；
- 照片描述会变成正文里的“图1、图2…”说明，并列在拍摄清单里（已拍 + 建议补拍）；
- 素材太少时会补一两段本细分的专业知识；AI 模式会更自然地组织语言，但只使用素材里的事实；
- 生成的卡片上有「💾 存为案例」，也可以不生成、直接点「💾 直接存为案例」，确认后存进案例库。

## 🗓 内容日历

「🗓 日历」：选择行业 / 细分（或填写主题方向）、账号档案、开始日期和天数（7 / 14 / 30 天），设置干货 / 案例 / 避坑 / 互动的比例，点「🗓 生成规划」。

- 按比例分配并穿插排列，尽量不连续两天发同一类；
- 案例类选题会依次带入资料库里本行业的真实案例；
- AI 模式下由 Claude 写每天的选题标题和写作角度；
- 「⬇️ 导出 CSV」可以放进 Excel 或共享表格里排期；
- 点某一天的「✍️ 生成」，会自动填好行业、主题、语气、档案和案例，直接生成那天的笔记，并标记为“已生成”。

## 🔍 爆款拆解

「🛠 工具 → 🔍 爆款拆解」：粘贴一篇别人的爆款笔记（标题 + 正文），点「🔍 拆解」：

- **标题套路**：数字、提问、点名人群、避坑警示、情绪词、干货承诺、对比、真实体验等，并给出标题公式；
- **开头钩子**：身份式、结论先行、提问式、痛点式、数字式、故事式；
- **结构**：要点数量、是否有总结和互动结尾、字数、emoji 和话题标签数量。

然后填写你自己的主题，选择档案和案例，点「✍️ 仿结构重写」：只借鉴开头钩子类型、要点数量和结构，内容全部来自你的行业知识、档案和案例。重写后会**自动检查和原文连续 8 字以上重复的片段**，卡片上会显示原创检查结果。

> 请尊重原作者：只学结构和写法，不要照搬别人的内容和图片。

## 💬 评论 / 私信回复话术

「🛠 工具 → 💬 回复话术」：选择行业、账号档案、场景（评论区 / 私信），勾选常见问题（多少钱、能不能上门、质量、工期、保修、能不能便宜点、怎么联系、现货、案例…；潜水和美食行业有各自的问题），也可以自己写问题。

- 回复专业、有温度，不出现电话、微信、网址等站外联系方式，不承诺具体价格和效果；
- 会用到档案里的服务区域和特色；
- 每条回复都会做违禁词检测，有问题可以一键修正；
- 自定义问题在模板模式下只能给通用回复，AI 模式会针对性回答。

## ♻️ 一稿多用

每篇卡片右上角的「♻️ 一稿多用」：

- **🎬 抖音 / 视频号口播脚本**：开场 3 秒钩子 → 背景 → 每个要点配一个画面 → 案例 → 结尾引导，标注“🎤 口播”和“🎥 画面”，并估算时长。模板模式按笔记结构自动拆分，AI 模式更口语化。
- **🌐 English（Instagram / Facebook）**：按洛杉矶本地社区的习惯用英文重写（不是逐字翻译），保留价格、日期、城市等事实，附本地话题标签。**需要填写 API Key**（模板模式下只要填了 Key，也可以生成英文版）。

生成结果会保存在这篇笔记里，下次打开直接显示。

## 📊 效果回填与统计

「📊 数据」：

- **效果回填**：每篇笔记可以勾选“已发布”，填写发布日期、点赞、收藏、评论、咨询数；可以按已发布 / 未发布筛选、按标题搜索，点「查看」回到那篇笔记；
- **效果统计**：已发布篇数和各项总数、平均数；按行业、语气风格、内容来源（批量生成 / 素材变笔记 / 爆款仿写 / 内容日历）、是否带入真实案例分组对比；以及效果最好的 5 篇；
- 「⬇️ 导出数据 CSV」可以拿去做更详细的分析。

## 💾 备份与迁移（手机 ⇄ 电脑）

数据都存在浏览器本地，换设备或换浏览器前记得备份：

1. 在旧设备打开「📊 数据 → 💾 备份与迁移」，点「⬇️ 导出全部数据」，得到 `xhs-backup_日期.json`（包含档案、案例、历史与效果数据、内容日历、自定义违禁词、模型等设置，**不包含 API Key**）。
2. 把文件传到新设备（AirDrop、微信文件传输、网盘、邮件都可以）。
3. 在新设备打开工具，点「⬆️ 导入（合并）」或「⬆️ 导入（覆盖）」选择这个文件：
   - **合并**：保留新设备上已有的数据，加入备份里的内容（同一条记录以备份为准，不会重复）；
   - **覆盖**：先清空新设备上的数据，再导入备份。
4. 如果要用 AI 模式，在新设备的「⚙️ 设置」里重新填写 API Key。

> 浏览器的“清除浏览数据”、无痕模式都会让本地数据消失，建议定期导出备份。

## 🔑 怎么申请和填写 Anthropic API Key（AI 模式需要）

### 1. 申请 API Key

1. 打开 Anthropic 控制台：<https://console.anthropic.com/>，用邮箱注册并登录。
2. 进入 **Billing（账单）** 页面，绑定支付方式并充值少量额度（API 按用量计费，和 Claude 网页版会员是分开的）。
3. 打开 **API Keys** 页面：<https://console.anthropic.com/settings/keys>，点击 **Create Key**，起个名字（如 `xhs-tool`）。
4. 复制生成的 Key（以 `sk-ant-` 开头）。**Key 只显示一次**，请妥善保存。

> 费用参考：每生成一篇大约消耗几千个 token。具体价格请以 Anthropic 官网定价为准；想省钱可以在设置中选择 Sonnet 或 Haiku 模型。建议在控制台为这个 Key 设置用量上限。

### 2. 在工具里填写

1. 点击页面右上角 **⚙️ 设置**。
2. 把 Key 粘贴到「Anthropic API Key」输入框。
3. 选择模型（默认 Claude Opus 5.5，质量最好；Sonnet 5.5 更快更省；Haiku 5.5 最便宜）和并发数（默认 2）。
4. 可以先点 **测试连接**，看到「✅ 连接成功」后点 **保存**。
5. 回到主界面，选择「✨ AI 模式」，点「开始生成」。

### 🔒 关于 Key 的安全

- Key **只保存在你当前浏览器的 localStorage** 中，本工具**没有任何后端服务器**。
- 生成时，浏览器会把 Key **直接**发送到 Anthropic 官方接口 `https://api.anthropic.com`，**不会上传到本站、GitHub 或任何第三方**。代码全部公开在 `app.js`，可以自行检查。
- 在公共电脑或别人的设备上使用后，请到设置里点 **清除 Key**。
- 不要把带有 Key 的截图发给别人；如果怀疑泄露，到 Anthropic 控制台删除该 Key 重新生成即可。

### 想扩充或修改行业模板？

直接编辑 `industries.js`。每个行业包含：

- `ai`：AI 模式下附加给 Claude 的行业背景和专业要求
- `titles` / `openers` / `summaries`：按四种语气分组的标题公式、开头、总结
- `ctas`、`tags`、`coverMain`、`coverSub`：互动引导、行业话题标签、封面主/副标题公式
- `subs`：细分方向，每个细分有 `terms`（专业词汇）、`facts`（干货知识段落）、`pitfalls`（避坑段落）、`highlights`（种草/体验段落）、`tags`、`shots`（拍摄清单）、`scenes`（中英文生图场景）

占位符：`{t}` 主题、`{p}` 人群、`{s}` 细分简称、`{c}` 洛杉矶城市/区域、`{k}` / `{k2}` 关键词、`{term}` 行业专业词、`{n}` 正文要点数（自动和正文段落数一致）。

「通用」行业的模板在 `templates.js` 里的 `TITLE_FORMULAS`、`OPENERS`、`POINTS`、`SUMMARIES`、`CTAS`、`GENERIC_TAGS`。
